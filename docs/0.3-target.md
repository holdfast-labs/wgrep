# wg 0.3 changelog and release record

Status: released in v0.3.0.
Checkboxes record maintainer-reviewed work, not self-reported claims.

## Release goal

Make semantic results easier to scope and use. Remove repeated result regions.
Make index status clear. Keep exact search compatible with ripgrep 15.1.

## Changelog

- Add semantic directory and file scope within an attached root.
- Add repeatable `--semantic-glob` include/exclude filters for places to search.
- Apply scope before candidate selection and score normalization. Reuse the attached index.
- Remove substantial overlap between same-file semantic hits before filling the shortlist.
- Add an explicit raw-similarity cutoff. Return `[]` and exit 1 when all results fail it.
- Explain that relative and fused scores are ranking values, not confidence.
- Reduce weak natural-language file-name boosts, subject to a focused quality check.
- Distinguish a pending text rescan from active work and failed watcher trust.
- Define semantic and text file counts. Fix any reproduced create/delete count or freshness defect.
- Update the agent guide with scope, filtering, score limits, rescan states, and explicit `-n` examples.
- Diagnose first-query idle latency with existing timing evidence before choosing a performance fix.
- Test scope rules once per consecutive file run, rather than once per chunk.
- Align the quality tool with the 0.3 ranker and add an isolated idle-latency probe.

## Validation policy

- Prefer small regression fixtures for meaningful behavior.
- Run targeted checks for an affected package after a stable change.
- Stop after two failed attempts at one blocker and report it.

## Deferred decisions

- Default relevance cutoff: needs code/text model calibration across more than one query and repository.
- Blanket CSV/data-extension exclusions: query scope and filters come first.
- JSON canonical-path changes: retain long-path and UNC access until a concrete client failure justifies a format change.
- Exact-search automatic line numbers: retain ripgrep behavior; document `-n`.
- Idle-latency fix: choose only after measurement identifies the cause.

## Evidence and limits

The initial review used the 0.2.0 source. The external feedback corpus is not available here.
The feedback's timing table shows `wg` about 1.4–1.7 times faster than `rg`, contrary to its slower-than-rg wording.
Those Windows timings remain external observations, not release benchmark results.
Correct exact-search output after deletion does not prove semantic freshness.
